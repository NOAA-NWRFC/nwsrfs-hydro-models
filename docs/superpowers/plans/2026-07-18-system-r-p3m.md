# System R + P3M Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the repo's R toolchain from pixi/conda to the system R (rig), with renv pulling precompiled binaries from Posit Package Manager.

**Architecture:** pixi keeps the Python toolchain and drops its five R dependencies; `R` then resolves to `/usr/local/bin/R` (rig) through the inherited PATH. renv becomes the working local R environment: its lockfile points at P3M and the pixi R tasks run inside the renv project instead of disabling the autoloader. CRAN's gfortran is a documented one-time prerequisite. CI does not change.

**Tech Stack:** pixi (deno task shell), R 4.6.1 via rig, renv 1.2.0, Posit Package Manager, CRAN gfortran 14.2.

**Spec:** `docs/superpowers/specs/2026-07-18-system-r-p3m-design.md`

## Global Constraints

- P3M repository URL, exact: `https://packagemanager.posit.co/cran/latest`
- System R is rig's default: R 4.6.1 at `/usr/local/bin/R`
- CRAN Fortran toolchain at `/opt/gfortran` (gfortran 14.2 universal)
- pixi loses exactly these dependencies: `r-base`, `r-testthat`, `r-devtools`, `r-roxygen2`, `r-pkgdown`; everything else stays
- CI workflows are untouched
- CRITICAL pixi task shell rule: deno_task_shell expands `$var` even inside single quotes (verified: `'$path.sep'` becomes `.sep`). R code in pixi task commands must never contain `$` — use `[["name"]]` accessors, e.g. `.Platform[["path.sep"]]`, never `.Platform$path.sep`.
- R tasks follow the repo's existing error idiom: `status <- system2(...); if (!identical(status, 0L)) quit(status = status)`
- Commits: `<type>: <description>` (chore/docs/feat/fix), signed, no Co-Authored-By
- Do not commit `nwsrfsr_*.tar.gz`, `*.Rcheck/`, or `nwsrfs_r/renv/library/` (all gitignored)

- [ ] **Step 2: Replace the R task definitions**

Reminder (Global Constraints): no `$` anywhere in these command strings — deno_task_shell expands `$var` even in single quotes. That is why the code below says `.Platform[["path.sep"]]`.

```toml
install-r = { cmd = "Rscript -e 'Sys.setenv(R_LIBS = paste(.libPaths(), collapse = .Platform[[\"path.sep\"]])); status <- system2(\"R\", c(\"CMD\", \"INSTALL\", \".\")); if (!identical(status, 0L)) quit(status = status)'", cwd = "nwsrfs_r", description = "Install R package into the renv library" }
test-r = { cmd = "Rscript -e 'setwd(\"tests\"); testthat::test_check(\"nwsrfsr\")'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Run R tests" }
build-r = { cmd = "R CMD build nwsrfs_r", depends-on = ["install-r"], description = "Build R source tarball" }
check-r = { cmd = "Rscript -e 'Sys.setenv(R_LIBS = paste(.libPaths(), collapse = .Platform[[\"path.sep\"]])); f <- Sys.glob(\"../nwsrfsr_*.tar.gz\"); if (length(f) != 1) stop(\"Expected one nwsrfsr_*.tar.gz file\"); status <- system2(\"R\", c(\"CMD\", \"check\", \"--no-manual\", \"-o\", \"..\", f)); if (!identical(status, 0L)) quit(status = status)'", cwd = "nwsrfs_r", depends-on = ["install-r", "build-r"], description = "R CMD check (no manual)" }
check-r-cran = { cmd = "Rscript -e 'Sys.setenv(R_LIBS = paste(.libPaths(), collapse = .Platform[[\"path.sep\"]])); f <- Sys.glob(\"../nwsrfsr_*.tar.gz\"); if (length(f) != 1) stop(\"Expected one nwsrfsr_*.tar.gz file\"); status <- system2(\"R\", c(\"CMD\", \"check\", \"--as-cran\", \"-o\", \"..\", f)); if (!identical(status, 0L)) quit(status = status)'", cwd = "nwsrfs_r", depends-on = ["install-r", "build-r"], description = "CRAN submission check on built tarball" }
check-win-devel = { cmd = "Rscript -e 'devtools::check_win_devel(\".\")'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Submit to win-builder (R-devel); results emailed to maintainer" }
check-win-release = { cmd = "Rscript -e 'devtools::check_win_release(\".\")'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Submit to win-builder (R-release); results emailed to maintainer" }
check-win-oldrelease = { cmd = "Rscript -e 'devtools::check_win_oldrelease(\".\")'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Submit to win-builder (R-oldrelease); results emailed to maintainer" }
check-mac-release = { cmd = "Rscript -e 'devtools::check_mac_release(\".\")'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Submit to macOS builder (R-release); results emailed to maintainer" }
build-docs-r = { cmd = "Rscript -e 'pkgdown::build_site(install = FALSE, preview = FALSE)'", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Build R pkgdown docs" }
build-docs-r-readme = { cmd = "quarto render README.qmd --to html -M embed-resources:true -o README.html", cwd = "nwsrfs_r", depends-on = ["install-r"], description = "Build R README.html" }
```

Notes on intent, in case a command needs debugging:
- `Sys.setenv(R_LIBS = ...)` propagates the renv library (first in `.libPaths()`) to the `R CMD` child process, so `INSTALL` targets the renv library and `check` finds testthat.
- `check-r`/`check-r-cran` gain `-o ..` because cwd moved into `nwsrfs_r/`; the `.Rcheck` dir and glob target stay at the repo root as before.
- `test-r` starts Rscript in `nwsrfs_r/` (renv activates via `.Rprofile`), then `setwd("tests")` preserves the old `test_check` semantics against the installed package.
- `check-win-*`/`check-mac-release` pass `"."` instead of `'nwsrfs_r'` because cwd moved.
- `build-docs-r-readme` gains `depends-on = ["install-r"]`: quarto's knitr engine starts R in `nwsrfs_r/`, which now activates renv, so chunks needing nwsrfsr must find it in the renv library.
- `test-all`, `build-docs`, `check-online`, and all Python tasks are unchanged.

Insert after the opening paragraph ("...Not part of the package or the CRAN build."):

```markdown
## R development environment

R is not managed by pixi. Install and switch R versions with
[rig](https://github.com/r-lib/rig):

    rig list             # installed versions
    rig add release      # install the current release
    rig default 4.6      # pick the default R

Two one-time prerequisites:

1. CRAN's Fortran toolchain, which R's Makeconf expects at `/opt/gfortran`:

       curl -fLO https://mac.r-project.org/tools/gfortran-14.2-universal.pkg
       sudo installer -pkg gfortran-14.2-universal.pkg -target /

2. The R development packages (testthat, pkgdown, devtools, roxygen2),
   restored into the project library by renv:

       cd nwsrfs_r && Rscript -e 'renv::restore()'

renv installs from Posit Package Manager
(`https://packagemanager.posit.co/cran/latest`), which serves precompiled
binaries for macOS, Windows and major Linux distros, so restores do not
compile from source. The pixi R tasks (`pixi run test-r` and friends) use
the system R and this renv library; only the Python toolchain still comes
from conda. Maintainer-only packages are declared in
`nwsrfs_r/dev-dependencies.R` so `renv::snapshot()` keeps them in the
lockfile.

[rv](https://github.com/A2-ai/rv) is a likely successor to renv here (a
declarative lockfile-first manager), but it was pre-1.0 (v0.19) as of July
2026. Revisit once it reaches 1.0.
```
